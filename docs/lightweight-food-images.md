# 전체 메뉴의 저용량 음식 이미지

2026-09-10 사용자 요청: 고품질 사진 대신 음식이 구분될 정도의 저용량 이미지로 연결하고, 추후 한꺼번에 교체한다.

## 범위와 구현

- 현재 일반 추천 풀 294개 이름을 모두 별도 이미지 칸에 연결했다. 메뉴 추천 계산과 메뉴 목록은 변경하지 않았다.
- 기존에는 음식 12종 이미지가 있었지만 실제 추천 풀과 정확히 일치하는 이름은 8개였다. 이번 매핑은 서버의 실제 메뉴 집합과 일치하는지 검사한다.
- 내장 imagegen으로 7열 × 6행 음식 일러스트 7장을 제작했다. 각 칸은 특정 메뉴 하나이며, 카테고리 이미지에 임의로 묶지 않는다. 참고용 일러스트이므로 식재료 비율·가게별 조리법까지 재현한 제품 사진은 아니다.
- 웹용으로 각 칸 128px, 묶음 896 × 768px WebP로 내보냈다. 외부 이미지 주소를 사용하지 않는다.
- 이미지 전체 532,124바이트, 연결 스크립트 7,532바이트. 추천 두 메뉴를 표시할 때 필요한 이미지 묶음은 최대 2개, 합계 최대 160,798바이트다. 이전 음식 PNG 한 장은 2,222,115바이트였다.
- 새 카탈로그에는 294개를 모두 명시적으로 연결했다. 목록 밖의 신규 이름이나 연결 스크립트 로딩 실패 시 이름은 유지하고 잘못된 음식을 대신 표시하지 않는다.

## 교체 방법

`assets/food-thumbnails-v1/manifest.json`의 각 묶음 안 메뉴 순서가 행 우선 이미지 칸의 순서다. 원본 생성 요청은 따뜻한 흰 배경, 작은 음식 일러스트, 글자·테두리 없음, 정확한 7열 × 6행 배치였으며 모든 메뉴 이름을 해당 순서로 전달했다.

메뉴 순서를 유지한 새 그림 7장을 준비하고 `scripts/build_food_thumbnails.py --sources` 뒤에 순서대로 원본 경로를 전달하면 WebP와 연결 스크립트를 다시 만든다. 메뉴가 늘어나거나 이름이 바뀌면 manifest도 수정해야 한다. 서버 메뉴 집합과 연결표가 다르면 검사가 실패한다. 향후 별도 개별 이미지 체계로 바꾸어도 추천 로직은 변경할 필요가 없다.

## 확인

- 실제 서버 메뉴 294개와 연결표의 집합 일치 및 중복 없음.
- 294개 전부 실제 프런트 렌더링 함수에서 이미지·메뉴 제목 연결 확인.
- 미등록 메뉴 및 연결 스크립트 누락 시 글자 표시 유지 확인.
- 기존 조사·소품 매칭·옷차림 선택 검사 통과.
- 첫 화면, 연결 스크립트, WebP 7개 모두 ASGI 200 응답 및 이미지 MIME 확인.
- 제작 원본의 42칸 순서를 각 묶음별로 확인하고 압축본을 검토했다. 인증 후 실제 화면의 브라우저 시각 검수는 이번에도 포함하지 않는다.
