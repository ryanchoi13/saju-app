# SAZU 음식 추천 시험 연결

2026-10-05. 요청: SAZU 결과를 그대로 적용하고 며칠 실제 사용해 판단한다.

## 준비된 동작

- 서버에서 `POST https://api.sazu.app/v2/sazu/food` 호출. `foodRotation=daily`.
- 이름·계정 ID는 전송하지 않고 출생 입력과 기준 날짜를 보낸다.
- `SAZU_FOOD_TRIAL_USERS`에 등록한 정확한 계정만 사용한다. 미설정 시 기존 방식.
- SAZU의 `foodBalance`를 그대로 저장하고 표시한다. 기존 한열·열량 점수를 적용하거나 완성 메뉴를 지어내지 않는다.
- 곡류·국·단백질·반찬·음료·간식, 추천 이유, 순환 안내, 주의·면책을 표시한다. 아침·점심·저녁과 칼로리는 SAZU가 주지 않는 값이므로 만들지 않는다.
- 계정/날짜별 서버 저장으로 정상 저장 후 반복 접속에 추가 호출하지 않는다. 기존 추천과 저장 공간을 분리하며 끄면 기존 기록으로 돌아간다.
- 출생지가 없는 현재 프로필은 SAZU 기본값 서울을 사용하며 화면에 명시한다. 시진 입력은 기존 달하의 대표 시각 변환을 유지한다.
- 유료 키·오류 응답·다른 사주 모듈을 브라우저로 보내지 않는다. 실패하면 기존 추천을 SAZU 결과로 가장하지 않는다.

## 활성화 전 필요한 확인

1. 유료 SAZU API 키를 서버 환경변수 `SAZU_API_KEY`에 설정한다. 키를 채팅이나 저장소에 넣지 않는다.
2. 동일 서버의 `SAZU_FOOD_TRIAL_USERS`에 시험할 `user_...` 계정 ID를 설정한다. 이 값은 공백 제거 후 정확히 일치해야 한다.
3. 실제 유료 응답으로 계약 확인: `data.modules.foodBalance`, basket의 항목 구조, cautions 문자열 배열, disclaimer 문자열을 확인한다. 현재 테스트 데이터는 공개 문서 기반의 가상 응답이며 실제 SAZU 결과가 아니다.
4. 모바일에서 계정 로그인 → 음식 영역 → 재접속 시 동일 결과 → 다음 날 결과 확인. 오류·주의 문구·불필요한 기존 버튼이 없는지 확인한다.
5. 날짜별 실제 출력으로 반복과 일상성을 평가한다. 현재 키가 없어 라이브 결과 품질은 미검증이다.

Render 연결 도구는 작업공간 확인을 요구한다. 조회된 후보는 `saju`이며 사용자가 작업공간을 확인하기 전 운영 환경은 변경하지 않았다.

## 검증 및 한계

문서: https://www.sazu.app/manse-api/docs (2026-10-01, v2).
공개 문서에는 weekly가 닷새/일주일로 혼재하여 이번 시험은 기간 식단을 요청하지 않는다.
API는 음식 재료·상차림 구성 중심이다. 세계 음식 완성 메뉴까지 제공한다고 가정하지 않는다.
응답 스키마와 유료 키가 검증되기 전에는 시험 계정을 활성화하지 않는다.

로컬 검증: `PYTHONPATH=. python3 -m unittest discover -s backend/tests -p test_sazu_food_trial.py`.
오류·원문 보존·음력/윤달/미상 시각·계정 제한·캐시 분리·토큰·날짜 변경을 검사한다.
롤백: `SAZU_FOOD_TRIAL_USERS`를 비우면 기존 음식 엔진으로 돌아간다.
