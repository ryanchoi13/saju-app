## 동작 비교

정리 전후 아래 결과를 정규화한 JSON으로 직렬화하여 순서까지 비교했다.

- 코디: 120개 배색 × 2성별 × 4계절 × 6착장 = 5,760벌. 나이 입력은 50세로 고정했다.
- 음식: 가상 출생정보 4개 × 기준일 7개 × 오행 가중치 8개 = 순위 응답 224건.
- 공통 해석: 같은 출생정보 4개 × 기준일 7개 × 해석 범위 5개 = 140건.

모두 일치했다. 전체 결과 SHA-256:

`7c338d31ea84b89732cfe484f3098275ebc446845ad82c5e4fa1978f148130f6`

별도 기존 검사도 통과했다.

- Python 69개: 코디 조화·실제 착장 규칙·SVG 연동·날씨·음식 순위·식단 목록/이미지·해석·일일 운세.
- 코디 DOM 검사: 요약, 게시 이미지, 팝업, 탭 등.
- 음식 DOM 검사: 순위 쌍, 독립 횟수 제한, 팝업 이력, 실패/중복 요청, 계정 분리, 자정 처리 등.

첫 Python 실행은 Pillow가 없는 검사 환경 때문에 이미지 검사 1개만 실패했다. 기존 런타임의 Pillow 경로를 추가해 그 검사를 다시 실행했고 통과했다. 운영 의존성은 바꾸지 않았다. 코디 DOM의 예전 문구 실패는 변경 전 코드에서도 재현한 뒤 예상값을 수정했다.

이 검사는 전체 연령·날씨 조합이나 실제 모바일 기기·운영 DB·브라우저 렌더링 속도를 전수 검증했다는 뜻은 아니다.

## 시간 측정

동일 환경의 Python 3.12.14에서 작업마다 1회 예열 후 9회 측정한 중앙값이다. 시간은 `perf_counter`로 측정했다. 다른 검사와 동시에 성능을 측정하지 않았다.

| 측정 단위 | 전 | 후 | 시간 감소 |
| --- | ---: | ---: | ---: |
| 코디 120개 배색 처리 (여성·가을, 총 720벌) | 805.44ms | 586.17ms | 27.2% |
| 음식 순위, 가상 사용자 4명 | 13.30ms | 4.19ms | 68.5% |
| 전체 응답 생성, 가상 사용자 4명 | 165.69ms | 112.18ms | 32.3% |

네트워크와 운영 DB를 제외한 로컬 계산 측정이다. 운영 페이지 체감 속도가 같은 비율로 빨라진다는 뜻은 아니다. 전체 응답 측정은 계정별 저장 기능을 사용하지 않았고, 실행일의 공통 응답 생성 함수를 호출했다. 결과 동일성 검사는 고정 날짜로 별도 수행했다.

원시 측정값은 `docs/benchmarks/recommendation-before.json`, `recommendation-after.json`에 보관했다. 저장된 재현 스크립트를 **비교하려는 버전의 저장소 루트**에서 실행한다.

```sh
python /path/to/benchmark_recommendation_maintenance.py /tmp/recommendation-result.json
```

재현 스크립트: `scripts/benchmark_recommendation_maintenance.py`. 성능 수치는 환경에 따라 달라질 수 있다.

## 후속 정리 순서

1. `main.py`의 코디·음식 응답 조립과 `index.html`의 기능별 화면 코드를 단계적으로 분리한다. 이미 엔진 자체는 상당 부분 모듈화되어 있으므로 전면 재작성은 필요하지 않다.
2. 계정별 당일 음식 순위가 저장되어 있으면 재계산을 생략하는 방안을 별도 검토한다. 현재 저장 결과와 새로 계산한 보조 응답 필드를 함께 사용하므로, 단순히 계산 순서만 바꾸면 반환 내용이 달라질 수 있다.
3. 구형 코디 데이터와 연구 자료는 참조 관계를 확인한 뒤 정리한다. 현재 화면이 쓰는 `style_palettes`와 현행 음식 풀이 불러오는 이전 데이터는 유지한다. 연구 출처·승인 이력도 보존한다.

FastAPI의 기존 시작 이벤트 폐기 예정 안내는 이번 변경과 무관하다. 향후 프레임워크 정비 때 다룬다.

이번 작업에서는 추천 기준이나 도안 변경, DB 수정, 대규모 파일 이동, 운영 배포를 수행하지 않았다.
