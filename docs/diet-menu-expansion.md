# 다이어트 메뉴와 음식 이미지 보완 · 2026-09-11

사용자가 제안 확인 후 수정·검증·배포를 승인했다. 디자인 A를 유지한다.

## 변경 이유

다이어트 메뉴 66종 중 이미지가 연결된 것은 5종뿐이었다. 포케 7종이 모두
목(木)으로 묶이고 토(土) 후보가 밥·국 위주여서, 당일 우선 오행에 따라 한식만
보이는 문제가 있었다. 스무디·오차즈케·파스타의 요리권 분류도 잘못 묶여 있었다.

## 메뉴와 추천

- 기존 66종을 유지하고 샐러드 6, 포케·곡물볼 4, 통밀 샌드위치 6,
  통밀랩 4, 채소·단백질 김밥 4종을 추가했다. 총 90종이다.
- 전체 목록, 주재료, 요리권, 음식 종류, 오행 선정 사유는
  `backend/app/engine/services/diet_catalog_revision.py`에서 음식별로 관리한다.
- 오행은 앱의 편집상 상징 분류다. 식품의 영양·건강 효과를 측정한 결과가 아니다.
  기존 음식 묶음 전체에 하나의 오행을 부여하던 방식에서 개별 주재료·조리 특징
  검토로 바꿨다. 양식을 노출하기 위해 특정 오행으로 일괄 지정하지 않았다.
- 분류 후 木 13, 火 17, 土 19, 金 20, 水 21종. 요리권은 양식 50,
  한식 31, 일식 5, 동남아식 4종이다. 포케는 음식 스타일상 양식으로 분류한다.
- **오행 점수 우선순위를 유지한다.** 같은 점수 안에서는 앞서 적게 나온 음식
  종류를 우선하고, 바로 이전 종류의 연속을 피한 뒤 요리권, 기존 대중성·접근성,
  날짜별 결정적 순서로 선택한다. 일반식의 기존 정렬·시드는 유지한다.
- 일반식 10세트, 다이어트식 5세트(첫 세트 포함), 전체 보기, 재접속 첫 세트,
  한국 날짜 기준 초기화 정책은 그대로다. 좋아요·개인화·혼합 끼니 계획은 추가하지 않는다.

## 이미지

- 기존 그림 6개(기존 다이어트 5개 + 새로 포함된 닭가슴살 그린샐러드 1개)를 재사용했다.
- 누락 61개와 나머지 신규 23개를 위한 그림 84칸을 내장 `image_gen`으로 제작했다.
  `assets/food-thumbnails-v1/food-08.webp`부터 `food-10.webp`까지 3장이다.
- 그림은 7열 × 4행, 896 × 512px WebP. 새 파일 합계 159,416바이트.
  일반식 포함 전체 10장의 이미지 합계는 691,540바이트다.
- 이미지 수는 두 풀의 합집합인 378개이며, 다이어트 90종 모두 정확한 이름으로
  연결된다. 일반식에서 쓰던 7장의 이미지와 잘림 좌표는 그대로 유지했다.
- 새 그림의 음식 경계와 행·열 간 여백을 측정해 잘림 좌표를 저장했다. 프런트는
  각 이미지의 실제 크기를 사용하므로 4행 그림을 6행 높이로 늘이지 않는다.
- 맑은 순두부 달걀탕이 붉은 찌개로 나온 생성 결과를 수정해 최종본에 반영했다.
- 생성 프롬프트와 최종 수정 프롬프트는 같은 폴더의
  `diet-generation-prompts.json`, 순서와 좌표는 `manifest.json`에 보관한다.
- `scripts/build_food_thumbnails.py`는 두 메뉴 풀과 이미지 연결표의 일치를 검사한다.
  새 그림만 재인코딩할 때는 `--sheet-start 7 --sources <3개 원본 경로>`를 사용한다.
  일반 카탈로그 재검증·출력은 인수 없이 실행한다.

## 적용 시점과 검증

- 이미지 연결은 배포 후 새 페이지 로드부터 적용한다.
- 이미 만들어진 당일 추천 목록과 조회 횟수는 변경하지 않는다. 새 메뉴와 분류는
  새 일일 추천 목록이 만들어질 때 반영된다. 당일 기록이 있는 사용자는 다음 한국 날짜부터다.
- SQL 저장 방식이나 스키마, 계정 정보, 옷장 데이터는 변경하지 않았다.
- 메뉴·기록·기존 식단 회귀 테스트 32개 통과. 5개 오행 각각에 대해 7일간
  순위 우선성·중복 없음·음식 종류 분산을 검증했다.
- 378개 실제 프런트 렌더링의 이미지 이름, 잘림과 원본 크기 확인.
  디자인 A/B의 다이어트 2개 카드와 전체 보기 10개 카드에서 그림 누락 없음 확인.
