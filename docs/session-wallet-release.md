# 로그인·복채 보존 수정 — 배포 승인 대기

## 변경
- 카카오 토큰 검증 후 발급한 HttpOnly/Secure/SameSite 쿠키로 계정을 확인한다. 기존 localStorage ID는 인증 수단으로 인정하지 않는다.
- 세션은 30일 유효하며 서버에는 토큰 해시만 저장한다. 로그아웃은 해당 세션을 폐기한다.
- 다른 사용자 ID를 지정한 개인 정보·옷장·메뉴·리포트·타로 요청은 거부한다. DB 장애 시 인증을 우회하지 않는다.
- account_sessions, account_assets 테이블을 기존 영속 저장소에 추가한다. 기존 테이블을 삭제하지 않는다.
- 복채와 리포트는 DB가 기준이다. 리포트 가격은 서버가 결정하며 재요청은 중복 차감하지 않는다.
- 유료 타로 영수증과 복채 차감을 같은 트랜잭션에 저장한다.
- 가상 충전은 서버 환경변수 DALHA_TEST_USER_IDS에 지정한 계정만 허용한다(쉼표로 구분한 user_카카오ID). 미설정 시 모두 거절한다. 실제 결제 연동은 없다. 충전당 최대 100,000, 잔액 최대 1,000,000 복채로 제한하고 DB에 저장한다. 배포 전 테스트 계정 지정이 필요하다.

## 승인 전 주의사항
- 배포 후 기존 이용자는 카카오 로그인을 한 번 다시 해야 한다.
- 이 변경은 앞으로의 자산 보존을 해결한다. 이전 서버 재시작으로 이미 사라진 메모리 잔액·리포트는 복원하지 못한다.
- 실행 중인 프로세스의 기존 캐시가 있으면 최초 DB 저장 시 반영하지만, 새 프로세스로 배포하면서 사라지는 메모리를 자동 이전할 수는 없다. 실제 유료 이용 내역이 있다면 배포 전에 별도 대조·이관이 필요하다.
- 로컬 검증은 격리된 SQLite와 가짜 카카오 응답으로 수행한다. 실제 카카오 로그인 및 운영 PostgreSQL 환경 확인은 별도 필요하다.
- Render 콜드 스타트 개선은 이번 범위에서 제외한다.
- 추가 배포는 사용자 최종 승인 후 진행한다.
